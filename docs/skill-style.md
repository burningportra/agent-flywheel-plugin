# Flywheel skill prose style

These rules apply to every file under `skills/` and every prompt the server sends to a Claude pane. They do not apply to prompts the server sends to Codex or Gemini panes — those have their own stylistic needs and are exempt.

## Rules

1. **Plain sentences, no shouting.** A frontier model follows calm prose at least as well as all-caps directives. Write "run the test" instead of "YOU MUST RUN THE TEST". No `MUST`, `NEVER`, `MANDATORY`, `STOP`, `CRITICAL`, `IMPORTANT`, `Do NOT`, `Hard rule` or similar framing when a declarative sentence does the same job. The lint rule `TONE001` counts these tokens per file and ratchets the count down over time.

2. **Tool facts stated once.** If a tool has a sharp edge, say it once in plain words: "use `ntm --robot-send`; `ntm send` hits a dedup prompt". Don't repeat the warning three sections later. If a reader needs the fact in two places, link to the first.

3. **At most one "Use ultrathink." per deep-reasoning subagent prompt.** Repetition inside the same prompt doesn't buy more depth; it just inflates the token budget.

4. **No quotas.** "Find at least 80 issues" and "surface 10x more findings" train agents to pad. Write "report every substantive issue; don't pad". The lint rule flags `AT LEAST`, `80+` and similar quota framings.

5. **Rationale and history live in `docs/design/`, not in skills.** Skill text is instructions a frontier model will act on now; design docs are context a human reads later. When a sentence starts with "The reason this works is …", it probably belongs in a design doc.

6. **Procedure a frontier model can work out becomes a one-line goal.** "Call `br list --json`, parse the JSON, filter by status, then …" is a procedure the model will reconstruct from "List open beads with `br list --json`." Keep the goal; drop the walkthrough.

7. **`AskUserQuestion` blocks stay verbatim.** The lint rule and tests parse them. Don't rewrite them for flow, don't collapse them to prose, don't abbreviate option labels or descriptions. If an AUQ block feels overlong, split the question into two.

8. **Prompts sent to Codex or Gemini panes are exempt from the tone rules.** Those models respond to a different register; let the adapter choose it. The exemption is scoped to the prompt body sent to those panes, not the surrounding skill prose.

## How the lint ratchet works

`TONE001` counts the discouraged tokens and quota phrases in each file, outside code fences and outside any `## Universal Rule` block. The committed baseline (`mcp-server/.lintskill-tone-baseline.json`) records today's count per file. A pull request that raises any file's count above its baseline fails CI; a pull request that keeps the count equal or lower passes. The baseline is regenerated by `npm run lint:skill:update-tone-baseline`, which runs the rule and writes the current counts — the point of the ratchet is that regeneration only ever lowers the ceiling.

New skill files get a count of 0 by default; the first pass that lands them pins the ratchet at the current count.

## Scope

The rule runs on `skills/start/*.md`, following M2's coverage. Other skill directories can opt in by adding their path to the dir runner's `--dir` list; the baseline covers whichever files the runner iterates over.
