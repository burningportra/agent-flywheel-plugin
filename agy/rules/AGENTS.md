# Agent Flywheel — rules for the Antigravity (AGY) mirror port

This file is the condensed companion of the repository's full `AGENTS.md`
(68 KB). It carries the rules an agent working in the repo must follow and
pointers to the long sections. The repository root is the plugin source of
truth; this mirror is regenerated by `scripts/sync-agy.sh` — never edit the
installed copy under `~/.gemini/`.

## Harness translation glossary

Skills and commands in this plugin were authored for Claude Code. Translate
tool references as you work:

| Claude Code | AGY | Notes |
| --- | --- | --- |
| `AskUserQuestion` | `ask_question` | Every decision gate routes through a user question. |
| `Bash` | `run_command` | Hook matchers and prose both use `run_command`. |
| `Agent()` / `Task` | `invoke_subagent` | Subagent fan-out for implementation work must go through NTM anyway (see below). |
| `Read` | `read_file` | |
| `Edit` | `edit_file` | |
| `Write` | `write_file` | |
| `Skill(...)` | `flywheel_get_skill` MCP tool | Load bundled skills with `flywheel_get_skill({ name: "agent-flywheel:<skill>" })`. Skill names keep the `agent-flywheel:` prefix here. |
| `ToolSearch` | none | Does not exist in AGY; skip that step — MCP tools load via the plugin's `mcp_config.json`. |

Slash references like `/agent-flywheel:start` refer to the bundled skill
`start` (commands are mirrored as `cmd-<name>` skills). `$ARGUMENTS` in a
command body means whatever the user typed after the command.

## Hard constraints (verbatim from the repo)

1. **No `console.log` in MCP server code.** The server uses stdin/stdout for JSON-RPC. Any stdout write corrupts the communication channel. Use `createLogger(ctx)` from `./logger.js` for all diagnostics — it writes structured JSON to stderr only.
2. **Never edit `mcp-server/dist/`.** It is compiled output. Edit sources in `mcp-server/src/` and rebuild.
3. **TypeScript strict mode.** `tsconfig.json` enables `strict: true`. All code must pass strict type checking.
4. **NodeNext module resolution.** Use `.js` extensions in all relative imports (e.g., `import { foo } from "./bar.js"`), even when the source file is `.ts`.
5. **ESM only.** `"type": "module"` in `package.json`. No CommonJS `require()`.
6. **Never write directly to `.pi-flywheel/checkpoint.json`.** Use `flywheel_*` MCP tools for state management.
7. **All `exec` calls must include a `timeout`.** No open-ended shell commands.
8. **Propagate `signal` through `exec` calls.** When the calling function receives an `AbortSignal`, pass it to every `exec()` call: `exec(cmd, args, { timeout, cwd, signal })`. The `ExecFn` type (from `exec.ts`) accepts `signal?: AbortSignal`.

## Build and release discipline

- Build with `cd mcp-server && npm run build` (compiles `src/` → `dist/`).
- `mcp-server/dist/` is committed so the plugin works with no build step on
  the user's machine. Any `src/` change must rebuild and commit `dist/` in
  the same PR; the `dist-drift` CI job fails out-of-sync PRs.
- The OpenCode port under `~/.config/opencode` and this AGY mirror are both
  derived artifacts produced by sync scripts from manifest-owned repo
  sources. Change the repo, re-run the sync. A hand-edited generated file is
  detected as `[LOCAL]` divergence, backed up, and overwritten — never a
  second source of truth.

## Code conventions

- Named exports only (no default exports). Types live in
  `mcp-server/src/types.ts`; import with `import type { ... }`.
- `ExecFn` from `mcp-server/src/exec.ts` wraps all shell execution; do not
  redefine it locally.
- Errors: throw `new Error(message)` in feature code; return structured
  envelopes at tool boundaries via `makeFlywheelErrorResult` from
  `mcp-server/src/errors.ts`. `FlywheelError` is the only permitted custom
  error class and must not be subclassed.
- Logging: `createLogger` from `mcp-server/src/logger.ts` only. Never
  `console.log`/`console.error` (constraint 1). Level via `ORCH_LOG_LEVEL`.
- Prefer `Promise.allSettled` for parallel operations where partial results
  are acceptable; prefer async functions over callbacks.
- Tests: Vitest, files in `mcp-server/src/__tests__/`. Run with
  `cd mcp-server && npm test`. Always add a regression test when fixing a
  bug. Skill-markdown changes under `skills/start/` must pass
  `npm run lint:skill`.

## Agent Mail (mandatory coordination)

- Bootstrap your session first:
  `am macros start-session --project <repo> --program <pi|cc> --model <model> --task "<task>"`.
- Before modifying any file, reserve it:
  `am file_reservations reserve <project> <agent> <paths...>`. Treat any
  non-empty `conflicts` array in the response as failure — the server issues
  the reservation anyway (known bug); the pre-commit guard is the second line
  of defense, do not bypass it.
- Report errors to the lead via mail with subject `[error] <context>`. Never
  silently skip a task.
- Check your inbox at task start for updates or cancellations.
- Transport: agent-mail is an HTTP MCP server at
  `http://127.0.0.1:8765/mcp` (`"type": "http"`; not `sse`, not `url`).
  Health: `curl -s http://127.0.0.1:8765/health/liveness` → `{"status":"alive"}`.
- Do not delete `.mailbox.activity.lock` or `storage.sqlite3.activity.lock`
  files, and do not run mutating `am doctor` commands while the service is
  up (the guard hook denies these); report Agent Mail health issues to the
  coordinator instead.

## NTM is mandatory for all spawned work

Every multi-agent spawn — planning fan-out, swarm waves, deslop sweeps,
reality-check follow-ups, parallel reviewers, ad-hoc "do these N things in
parallel" requests — must go through NTM (`ntm spawn` +
`ntm --robot-send`). Forbidden as substitutes: raw `Task`/`Agent` fan-out
onto multiple subagents, backgrounded `claude`/`codex`/`pi`/`gemini` shells,
hand-written `tmux split-window` invocations, and custom orchestrators
(`xargs -P`, GNU `parallel`, Makefile parallel targets) for work that
produces code or PRs.

Narrow exceptions: single-shot read-only research subagents that produce no
code; single foreground Bash invocations that complete in-band (linter,
test, build); Pi/AGY panes added by `mcp-server/dist/scripts/swarm-spawn.js`
(it owns the session's pane lifecycle).

Canonical swarm spawn (Claude : Pi : Gemini-lane at equal share; AGY panes
are an Antigravity transport for the Gemini seat — same model, `--agy`
lane):

```bash
node "${CLAUDE_PLUGIN_ROOT}/mcp-server/dist/scripts/swarm-spawn.js" <project> \
  --label <purpose> --cc=2 --pi=2 --pi-model=<provider>/<model> --gmi=2
```

Address panes by the printed `index` via `ntm --robot-send --panes=<index>`.
If a provider lane is unavailable the doctor's lane rows say so and the
substitution ladder (gmi→pi→cod→cc) applies. Deep plan runs
`--cc=1 --pi=2` (correctness + robustness + ergonomics planners).

## Bead lifecycle

After finishing an implementation, close the bead and verify the close:

```bash
br update <bead-id> --status closed
br show <bead-id> --json   # confirm "status": "closed"
```

Retry the update once if the second call shows anything else. The
coordinator also runs `flywheel_verify_beads` after each wave to auto-close
stragglers with a matching commit, but verify locally first.
`flywheel_review` reconciles bead state automatically (`looks-good` is
idempotent on closed beads); do not skip it.

## Pre-completion quality gate (every spawned implementor)

Before reporting any bead complete, in order:

1. **UBS scan** on changed files (`/ubs-workflow` skill, changed-files
   mode). Every finding must be fixed, filed as a new bead, or explicitly
   justified in the completion message.
2. **Repo verify commands** — the build/test/typecheck/lint commands
   relevant to the surfaces touched. No "looks fine locally".
3. **Self-review with fresh eyes** — re-read your own diff for regressions,
   unsafe assumptions, missing tests, edge cases.

The completion message must state (a) the UBS result (`clean` / `fixed N` /
`deferred to bead ids …`), (b) the verify outcome, (c) a one-line
self-review summary. Completions missing this evidence are rejected.

Additionally write the attestation JSON to
`.pi-flywheel/completion/<beadId>.json` matching `CompletionReportSchemaV1`
(`mcp-server/src/completion-report.ts`): `version: 1`, `beadId`,
`agentName`, `status: closed|blocked|partial`, `changedFiles[]` (repo-
relative, no absolute paths, no `..`), `commits[]`,
`ubs{ran,summary,findingsFixed,deferredBeadIds[]}`, `verify[]{command,
exitCode, summary}`, `selfReview{ran,summary}`, `beadClosedVerified: true`
(required for `closed`), `createdAt` (ISO-8601). Docs-only diffs: set
`ubs.ran=false` with a `skippedReason`. `flywheel_verify_beads` reads this
file; `flywheel_advance_wave` gates on it.
